## 模块说明

本模块解决一个问题：**模型是怎么"看到"文字的？**

神经网络只能处理数字张量，不能直接处理字符串。所有文本在进入模型之前，
都要先被切分成 Token，再换成整数 ID。这一步发生在模型之外，
却决定了模型能理解什么、能看多远、要花多少钱。

读完本篇应能回答：

1. Token 和"字""单词"有什么区别？
2. 为什么模型不直接以字符或整句为输入单位？
3. Tokenizer 是如何把一段文本变成一串 ID 的？
4. 上下文长度限制的本质是什么？

## 一、Token 是模型处理文本的基本单位

Token 不一定等于一个汉字、一个单词或一个完整词语。

```text
我喜欢学习人工智能
```

可能被拆成：

```text
我 | 喜欢 | 学习 | 人工 | 智能
```

也可能被拆成：

```text
我 | 喜 | 欢 | 学 | 习 | 人 | 工 | 智 | 能
```

具体如何拆分，取决于模型使用的 Tokenizer 与词表。

英文更明显：

```text
unbelievable
```

常见切分结果是：

```text
un | believ | able
```

因为词表里未必收录 `unbelievable` 这个整词，但收录了这三段高频片段。

---

## 二、为什么不直接用字符或整句

| 方案 | 问题 |
|---|---|
| 单个字符 | 序列变得很长，一个词的信息被摊到十几个位置上，模型要多算很多步 |
| 完整单词 | 词表规模巨大，新词、错别字、变体无法表示（未登录词问题） |
| 整句 | 句子组合近乎无限，不可能枚举成词表 |
| 子词 Token | 词表可控（几千到十几万），任意文本都能表示，长度适中 |

子词（subword）方案是当前的主流：**高频组合成一个 Token，
低频组合拆成若干片段**。这样既控制了词表大小，又保证任何输入都能被编码。

## 三、从文本到 Token ID 的完整链路

```text
原始文本
   |
   v
Tokenizer（切分成 Token 片段）
   |
   v
词表查表（片段 -> 整数 ID）
   |
   v
Token ID 序列
   |
   v
Embedding（见 02-embedding.md）
   |
   v
Transformer
```

一个具体例子：

```text
文本：      今天 | 天气 | 非常 | 好
Token ID：  1059   3322   1188   87
```

模型内部看到的全是最后这一行数字。ID 的大小没有任何顺序含义，
它只是一个索引，用来去 Embedding 表里取对应的向量。

## 四、动手验证：自己搭一个最小的 Tokenizer

下面这段代码实现的是最朴素的"词级 + 计数"Tokenization，
它体现了所有 Tokenizer 的共同结构：**统计 -> 建词表 -> 查表**。

```python
import collections

sentences = [
    "今天天气 非常 好",
    "今天天气 不错",
    "学习 神经网络 非常 有意思",
    "大语言 模型 学习 语言",
]

# 1. 统计频率
counter = collections.Counter()
for s in sentences:
    counter.update(s.split())

# 2. 按频率建词表，低频词归入 <unk>
vocab = {token: i + 1 for i, (token, _) in enumerate(counter.most_common(5))}
vocab["<unk>"] = 0

# 3. 文本 -> ID 序列
for s in sentences:
    ids = [vocab.get(t, vocab["<unk>"]) for t in s.split()]
    print(s, "->", ids)

print("词表：", vocab)
```

运行后会看到，出现次数少于阈值的词被统一压成 `<unk>`，
这正是真实 Tokenizer 里词表大小与覆盖率之间权衡的缩影。

真实的 BPE（Byte Pair Encoding）算法在此基础上多做一步：
从单个字符出发，反复合并出现频率最高的相邻片段，直到达到目标词表规模。

## 五、上下文窗口的本质是 Token 数量

模型有一个固定的最大输入长度，例如 4096 或 128K，
计量的都是 Token，不是字数，也不是行数。

同一段中文在不同词表下 Token 数可能相差数倍，因此：

- 一段文字大致占多少 Token，与词表设计直接相关。
- API 计费、显存占用、注意力计算量都按 Token 数增长。
- 注意力计算量随 Token 数呈平方增长（见 04-attention.md）。

---

## 六、常见误解

| 误解 | 实际 |
|---|---|
| Token 就是一个字或一个单词 | Token 是词表里的片段，长度不固定 |
| 数字 ID 越大越重要 | ID 只是查表索引，没有大小含义 |
| 模型能直接读字符串 | 模型只读 Token ID 和向量 |
| 词表越大越好 | 词表越大，Embedding 与输出层参数越多，需要权衡 |
| 中文和英文 Token 化方式相同 | 依赖具体词表，同一段文本 Token 数差别很大 |
